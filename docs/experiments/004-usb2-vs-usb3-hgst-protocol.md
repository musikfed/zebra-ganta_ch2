# Эксперимент 004 — сравнение USB–SATA адаптеров для HGST

**Статус:** протокол подготовлен, **новые измерения не проведены**. Дата подготовки: 13 ноября 2026.

## Цель

На том же HGST HTS725050B7E630 сравнить наблюдаемую пропускную способность и задержки чтения при подключении (A) через имеющийся мост JMicron USB 2.0 и (B) через док-станцию ORICO 6139C3-EU-CR-BP (по маркировке автора), USB-C ↔ USB-C, внешнее питание 12 В. Гипотеза: ограничение USB 2.0 участвует в наблюдаемом потолке последовательного чтения около 37–38 МБ/с. Это **не доказательство**, что разница задержек near/far вызвана только USB.

## Уже подтверждено

- В USBView выбран «USB to ATA/ATAPI bridge», производитель JMicron, **VID:PID 152D:2338**, `bcdUSB=0x0200`.
- `Device Bus Speed: High`; порт сообщает `USB 2.0: yes; USB 3.0: no`.
- Интерфейс USB Mass Storage, `bInterfaceProtocol=0x50` (Bulk-Only Transport).
- На этом стенде ранее наблюдали в основном 37–38 МБ/с через Windows + USB. Результаты нельзя считать скоростью поверхности HDD в изоляции.
- Необходимо сопоставить PnPDeviceID из `tools/usb-bridge-inspect.ps1` с JMicron, чтобы документально привязать USBView к конкретному HGST Disk 2. Пока эта привязка не предъявлена, её нельзя считать завершённой.
- Автор сообщил о подключении того же HGST через **ORICO 6139C3-EU-CR-BP**, кабель **USB-C ↔ USB-C** к USB-C ноутбука Acer, питание док-станции — **отдельное 12 В**. По USBView позднее подтверждено: мост VIA Labs **2109:0715**, фактически **SuperSpeed (5 Гбит/с)**, устройство Windows отображает как **SCSI (UAS)**. Измерения чтения HDD через ORICO **пока не предоставлены**.

## Порядок безопасного сравнения

1. **До переподключения:** сохранить все исходные CSV и манифесты опытов 001–003 на F:; не записывать ничего на HDD T:. Считать вывод `usb-bridge-inspect.ps1` для старого JMicron и зафиксировать USBView (VID/PID, Device Bus Speed, USB-протокол).
2. **Остановить обращения к диску:** закрыть файловые менеджеры, фоновые процессы и программы, которые используют исследуемый том. Штатно извлечь USB-диск через Windows, дождаться завершения операций и отключить питание/кабель. **Не подключать один и тот же SATA-диск к двум мостам одновременно.**
3. Подключить тот же HGST к док-станции USB 3.0, используя соответствующий кабель и порт USB 3.x ноутбука. Убедиться в стабильном питании и отсутствии ошибок подключения.
4. **Заново установить личность устройства:** номера `Disk N` и буквы тома после переподключения могут измениться! Использовать `Get-Disk`, `Get-CimInstance Win32_DiskDrive`, `Get-Partition` и USBView. Сверить модель HGST, ёмкости, отсутствие `IsSystem`/`IsBoot`, USB-тип, букву тома, VID/PID и действительный `Device Bus Speed`.
5. Если `usb-bridge-inspect.ps1` или `lab.py` завершаются защитным отказом из-за изменившегося номера, ёмкости, буквы или идентификатора, **не обходить защиту и не запускать старую команду сканирования**. Зафиксировать новые сведения и отдельно пересмотреть целевые параметры протокола/кода.
6. Сначала подтвердить режим соединения USBView: **High-Speed** (USB 2.0), **SuperSpeed** (USB 3.x) или иной. Не приравнивать возможность порта к фактической скорости.
7. Лишь после отдельной проверки устройства и условий повторить неизменённые, ограниченные **read-only** прогоны по существующим методикам, без форматирования, переразметки, изменения файловой системы и драйверов. Сохранять новые результаты на F:, а не на исследуемом HDD.
8. Записать время, температуру, режим питания, порт, кабель, мост, VID/PID, согласованную скорость, размер блоков, порядок точек, число повторов, предупреждения Windows и другие существенные условия. По возможности чередовать серии A/B и оценивать разброс между повторами, учитывая нагрев и кэши.
9. Сравнить отдельно последовательные МБ/с, медианные времена чтения near/far и разброс. Не выводить физическое время движения головки из задержек Windows+USB. Не утверждать ускорение алгоритма Zebra Ganta: здесь меняется **интерфейс подключения**, а не размещение данных.

Изменение самого USB-моста не доказывает ни физическую карту дорожек, ни эффективность макрополосного размещения.


## Программная обработка данных после двух реальных прогонов

Добавлен read-only анализатор `tools/compare_usb_bridges.py`, который принимает **только существующие CSV**; сам не обращается к устройствам, не создаёт результатов и не рассчитывает физическое время перемещения головки.

```powershell
cd F:\zebra-ganta_ch2
uv run python tools/compare_usb_bridges.py --usb2-scan results\USB2_СЕРИЯ\measurements.csv --usb3-scan results\USB3_СЕРИЯ\measurements.csv
```

Имена каталогов — **заполнители**, их нужно заменить реальными путями. Для near/far добавить `--usb2-transitions <путь-к-observations.csv> --usb3-transitions <путь-к-observations.csv>`. Анализатор сравнит медианы и предупредит, что изменение USB-моста не является доказательством эффекта алгоритма размещения.

**Существенный пробел в старом коде:** `lab.py` и `transitions.py` жёстко требуют `Disk 2` и сохранённый размер `Win32_DiskDrive`. В новом подключении номер, имя диска, характеристики моста и размеры могут отличаться. **До отдельной безопасной адаптации и повторной верификации не запускать опыт 001/003 на новом устройстве, не ослаблять проверки вручную.**


## USBView новой док-станции — фактически подтверждено

После подключения ORICO 6139C3-EU-CR-BP к USB-C ноутбука кабелем USB-C ↔ USB-C с независимым питанием 12 В получен текстовый отчёт USBView пользователя (13.11.2026):

- Порт №5 на втором контроллере xHCI: `USB 3.0: yes`, `Device Bus Speed: SuperSpeed`.
- USB VID:PID `2109:0715`; производитель контроллера `VIA Labs, Inc.`, продукт `VLI Product String`, `bcdUSB=0x0310`.
- В дереве Windows устройство отображается как «Запоминающее USB-устройство SCSI (UAS)». В дескрипторах видны альтернативные варианты `bInterfaceProtocol 0x50` (BOT) и `0x62` (UAS); отображение Windows согласуется с использованием UASP.
- В BOS заявлены SuperSpeed 5 Гбит/с и SuperSpeedPlus 10 Гбит/с, **но реально согласованное соединение: SuperSpeed 5 Гбит/с**, не 10.
- По одному только USBView ещё нельзя доказать соответствие выбранного USB-моста конкретному HGST без отчёта `lab.py inspect` / PnP-цепочки; абсолютная скорость и задержки при новом подключении пока **не измерены**.

**Методологический смысл:** сравнение теперь противопоставляет *JMicron + USB2 High-Speed + BOT* и *VIA Labs + USB3 SuperSpeed + UASP*. Оно не изолирует единственную переменную «версия USB»; новое подключение меняет также контроллер, протокол и питание.

## Фаза 1 после подтверждения ORICO SuperSpeed: инвентаризация, без чтения

Новое подключение USBView показало VIA Labs VID:PID 2109:0715, SuperSpeed, UAS; теперь требуется удостовериться, что этот мост ведёт именно к исследуемому HGST и Windows не перенумеровала диск. **Не запускать старые `lab.py scan` и `transitions.py` с фиксированным Disk 2.**

На Acer запустить по очереди:

```powershell
cd F:\zebra-ganta_ch2
git pull --ff-only origin main
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\exp004-preflight.ps1
uv run python lab.py inspect
```

Сохранить вывод `exp004-preflight.ps1` (Number, Model, GetDiskSize, Win32Size, Letters, PNPDeviceID, IsSystem/IsBoot) для сверки с ORICO. Программа не читает физические сектора и не пишет на диск.

Только если модель/ёмкости/тип USB/том и цепочка PnP соответствуют устройству, допускается последующий **ограниченный read-only** запуск `experiment004.py` с фактическими аргументами. `--link-speed Super --vidpid 2109:0715` — данные USBView, которые программа только записывает в манифест; их ещё требуется связать с HGST.

Для сопоставимости с опытом 001 параметры: `--samples 5 --mib 16 --repeats 3`. Для near/far: `--pairs 20 --seed 20261112`; по возможности повторить независимые серии. Результаты на F:. Не публиковать ничего как реальные измерения до появления CSV.
