# Эксперимент №005 — проверка эффекта порядка чтений HDD

**Статус: код и методика подготовлены, физический опыт НЕ ПРОВОДИЛСЯ.**

Цель — уточнить наблюдение опыта 004: медианы near резко отличались при смене порядка обращения. Из [исходного CSV 004](../../data/raw/exp004-usb3-orico/observations.csv): near-first около **5,43 мс**, far-first около **18,77 мс** (при сравнении near в разных группах). Это не доказывает физическое время перемещения головки; в опыте 004 порядок был смешан с другими свойствами серии.

## Схема ABBA — один набор адресов, разные порядки

Для **каждой** пары адресов (anchor, near, far) будут выполнены четыре раунда:

| Раунд | Первое целевое чтение | Второе целевое чтение |
|---|---|---|
| 1 | near | far |
| 2 | far | near |
| 3 | far | near |
| 4 | near | far |

Перед **каждым** целевым чтением делается опорное чтение anchor (по 4 КиБ), и оба времени отдельно записываются в CSV. В каждой паре near дважды идёт первым и дважды вторым; аналогично far. Используются те же адреса для всех четырёх раундов одной пары, но повторные запросы могут попасть в кэш. ABBA балансирует слот и порядок, **не исключает** кэш, прогрев, различную радиальную область, политику очередей и дрейф температуры. Четыре раунда подряд также могут усиливать эффект кэша: это осознанное ограничение пилотной версии.

**Границы опыта:** 20 пар (по умолчанию), 4 раунда × 2 целевых чтения = **160 целевых чтений** по 4 КиБ и столько же опорных, суммарно 320 обращений по 4 КиБ. Опционально 40 пар — удвоенный объём. Диск должен быть штатно подключён через ORICO (VIA Labs `2109:0715`, USBView SuperSpeed, том T:).

## Проверки безопасности

- По умолчанию `experiment005.py` **только печатает план**. Не открывает физический диск, не пишет файлы и не обращается к инвентаризации оборудования.
- Для реальных чтений требуется явный `--run`, затем сверка HGST по **обеим** ёмкостям, модели, USB, признакам загрузочного/system диска, букве **T:** и PnP-родителю **USB\\VID_2109&PID_0715**. Повторная проверка перед открытием.
- Никаких записей на T:, форматирования, установки драйверов или изменения разметки. Сырые чтения ограничены 4 КиБ в допустимых диапазонах.
- Результаты и manifest — **только** в `F:\\zebra-ganta_ch2\\results\\...-exp005-orico`.
- При ошибке чтения — отказ, `error.txt` и `observations_partial.csv` только на F: (если часть данных уже получена).
- Windows может не разрешить raw read. При отказе **не обходить** защиту и не переключать диск наугад.

## Запуск на Acer — по одной команде за раз

Обновить проект:

```powershell
cd F:\zebra-ganta_ch2
git pull --ff-only origin main
```

Посмотреть детерминированный план **без обращения к диску**:

```powershell
uv run python experiment005.py
```

Выполнить модульные тесты (без физического диска):

```powershell
uv run python -m unittest discover -s tests -v
```

Только после проверки версии кода и реального подключения ORICO возможен **отдельный live-прогон** (одной строкой):

```powershell
uv run python experiment005.py --run --disk 2 --letter T --size 500106780160 --win32-size 500105249280 --bridge usb3-orico --link-speed Super --vidpid 2109:0715 --pairs 20 --seed 20261115
```

Программа запросит фразу `READ HGST DISK 2 EXP005`. Обязательно перепроверить `Disk 2` и `T:` после любого переподключения. Без сохранения пользовательской команды с неверным номером диска.

## Анализ — только после настоящего прогона

Прочитать локальную папку результата:

```powershell
uv run python tools/report_exp005.py "results\ИМЯ_ПАПКИ_ИЗ_ВЫВОДА_EXP005"
```

Анализатор сопоставляет near и far внутри каждого из четырёх раундов для каждой пары, а также даёт отдельные медианы **первого** и **второго** целевых чтений. Сохранять исходные наблюдения и разброс, а не только одно число. Сравнение с 003/004 — лишь ориентир: экспериментальные условия не одинаковые.

**Критерий интерпретации:** если сильная зависимость от слота сохраняется после ABBA, её необходимо учитывать как самостоятельный фактор. Даже исчезновение эффекта не доказывает, что наблюдаемая разность равна истинному механическому seek-time. Любой вывод должен ссылаться на фактический CSV и описание условий.
