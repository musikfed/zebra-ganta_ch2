## 006. Перенос 1 ГиБ и конкурентные запросы

**Гипотеза**, а не результат: при большом объёме, множестве мелких файлов или при чередовании запросов к удалённым областям выигрыш от специальной раскладки может оказаться больше, чем при последовательном чтении.

Матрица сценариев: (A) один файл 1 ГиБ; (B) 4096 файлов по 256 КиБ, суммарно 1 ГиБ; (C) архив этих файлов с отдельно учитываемой стоимостью упаковки/распаковки; (D) несколько конкурентных потоков (1, 2, 4) с фиксированными и перемешанными последовательностями. Если размер архива отличается из-за сжатия, сравнение по номинальному размеру некорректно: нужно фиксировать фактически прочитанные байты и полезные данные.

**Строго отделяем**: генерацию логического плана (без дисковых операций); чтение существующего набора (только после проверки источника); реальное копирование и запись (только по отдельному, явно разрешённому протоколу на безопасный тестовый накопитель). Диск T: является текущим исследовательским образцом и не используется как место для автоматически создаваемых тестовых файлов; запись или перемещение на нём не включены. Нельзя считать тест на SSD F: доказательством выигрыша HDD.

Метрики: суммарное время, полезные МБ/с, задержки p50/p95/p99, число файлов и открытий, порядок запросов, количество конкурентных задач, контрольный хеш содержимого, фактически прочитанные/записанные байты, кэш и повторяемость. Для реального теста алгоритма надо доказать, что контрольная и «Зебра»-раскладки действительно различаются, показать их карту и стоимость их создания; симулятор сам этого не подтверждает.

## 007. Границы островков

Файловый объект → VCN → LCN/экстенты → раздел/LBA → неизвестные физические дорожки. В Windows FSCTL_GET_RETRIEVAL_POINTERS возвращает для выделенных частей файла соответствие VCN→LCN, но **не** магнитные координаты. Источник Microsoft: https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_get_retrieval_pointers.

Будущий инструмент: только чтение карты экстентов **у файлов, доступных на чтение**, получение размера кластера/тома, CSV границ и визуальной шкалы. Запрет на дефрагментацию, запись, обнуление, изменение разделов, попытку получить скрытую информацию о сервосекторах. Несовместимые файловые системы/разреженные участки фиксировать явно.

## 008. Механика, торможение и ресурс

Шпиндель при 7200 об/мин: 120 об/с, 8,33 мс/оборот, приблизительно 754 рад/с. Это расчёт от паспортных оборотов. Головка перемещается приводом с голосовой катушкой: разгон, управляемое замедление, установление. Без датчика угла и внутренней сервотелеметрии мгновенную скорость движения головки нельзя восстановить из задержки Windows USB. Динамическое торможение шпинделя при выключении **не** является методом ускорения чтения. Управление моторами и прошивкой в тест не включено.

Для сравнения ресурсных последствий нужны независимые данные о суммарной записи, времени, температуре, нагрузке, парковках, ошибках и доступности SMART. По одному профилю задержек нельзя вычислить увеличение ресурса.

### Следующий безопасный шаг 007 — только карта экстентов выбранного существующего файла

Добавлена утилита [`tools/inspect_extents007.py`](../../tools/inspect_extents007.py). **По умолчанию PLAN ONLY**, необходим явный `--file` с путём к существующему файлу на `T:\`. Лишь при `--run` она сверяет точный HGST, номер Disk 2, два размера, букву T:, NTFS и PnP-предка VIA Labs 2109:0715, затем запускает **`fsutil file queryextents` для одного файла**. Никаких данных файла, дефрагментации, изменений тома, raw-чтений и записи отчёта. Сырой вывод `fsutil` — отображение **логических NTFS экстентов**, не физических магнитных островков. На Windows совместимость и разрешения **ещё не проверены**: если утилита откажет, не обходить запрет.

Пример **только после выбора автором не секретного обычного файла на T:**:

```powershell
uv run python tools/inspect_extents007.py --file "T:\TestData\sample.bin"
```

Не выполнять `--run` до проверки нового кода и корректного файла. Не публиковать названия личных файлов и пути в отчётах.


## Проверка №007 на Acer — 13.11.2026

Автор обновил репозиторий до `2a1ab3b` и выполнил `uv run python -m unittest discover -s tests -v`: **24 теста OK (0,082 с)**. Команда `uv run python tools/inspect_extents007.py --file "T:\TestData\sample.bin"` дала ожидаемый вывод `PLAN ONLY`, без доступа к устройству или файлам. Этот путь **пример**, реальное существование файла не проверено.

`Get-ChildItem T:\ -File | Select-Object -First 10 Name,Length` ничего не вывел. Это означает только отсутствие видимых обычных файлов **непосредственно в корне** T: в этой выборке. Каталоги, вложенные, скрытые и системные файлы ещё не исследованы; том **нельзя** объявить пустым по такому выводу.

Следующее безопасное действие: **только перечисление** файловой системы, без чтения содержимого и без записи:

```powershell
Get-ChildItem -LiteralPath T:\ -Force | Select-Object Mode,Name,Length
Get-ChildItem -LiteralPath T:\ -File -Recurse -Force -ErrorAction SilentlyContinue | Select-Object -First 10 FullName,Length
```

Вторая команда при большом количестве элементов или ошибках может работать долго; при необходимости прервать Ctrl+C. Не публиковать личные пути. Если существующих неслужебных файлов нет, опыт 007 **остаётся без данных**: не запускать `--run` на несуществующем примере и не создавать тестовые файлы на защищённом HDD без отдельного протокола записи. Команда `fsutil file queryextents` ещё **не испытывалась** на выбранном файле.


## Инвентаризация HGST T: после проверки №007 — 13.11.2026

Автор подтвердил:

```powershell
Get-ChildItem -LiteralPath T:\ -Force | Select-Object Mode,Name,Length
```

Вывод содержит только каталог `System Volume Information` (атрибуты `d--hs-`). Запрос обычных файлов по вложенным каталогам с `-File -Recurse -Force -ErrorAction SilentlyContinue` **не вернул строк**. Это позволяет заключить, что в рамках выполненного перечисления **доступных обычных файлов для картирования экстентов не найдено**. Но из-за `-ErrorAction SilentlyContinue`, возможных ограничений доступа, наличия NTFS-метаданных и уже освобождённых/переназначенных секторов нельзя утверждать, что поверхность диска физически пуста.

**Следствие:** опыт 007 с `fsutil file queryextents` **не запускался**: подходящего существующего пользовательского файла нет. Не обращаться к `System Volume Information`, не ослаблять права, не создавать файлы «по умолчанию».

**Дальнейшее предложение (только проект протокола):** на явно выделенном тестовом томе сформировать два варианта одинакового полезного массива 1 ГиБ: один крупный файл и 4096 объектов по 256 КиБ; фиксировать формат, хеши, объём фактической записи, свободное место, точки extents и повторяемость. Размещение «Зебры» сравнивать только после реализации и подтверждения реальной раскладки. Любые создание или перемещение файлов являются **операциями записи**, требуют отдельного согласия владельца и проверки резервных копий. До этого допускаются только синтетические трассы и чтение метаданных.
