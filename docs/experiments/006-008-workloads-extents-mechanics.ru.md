## 006. Перенос 1 ГиБ и конкурентные запросы

**Гипотеза**, а не результат: при большом объёме, множестве мелких файлов или при чередовании запросов к удалённым областям выигрыш от специальной раскладки может оказаться больше, чем при последовательном чтении.

Матрица сценариев: (A) один файл 1 ГиБ; (B) 4096 файлов по 256 КиБ, суммарно 1 ГиБ; (C) архив этих файлов с отдельно учитываемой стоимостью упаковки/распаковки; (D) несколько конкурентных потоков (1, 2, 4) с фиксированными и перемешанными последовательностями. Если размер архива отличается из-за сжатия, сравнение по номинальному размеру некорректно: нужно фиксировать фактически прочитанные байты и полезные данные.

**Строго отделяем**: генерацию логического плана (без дисковых операций); чтение существующего набора (только после проверки источника); реальное копирование и запись (только по отдельному, явно разрешённому протоколу на безопасный тестовый накопитель). Диск T: является текущим исследовательским образцом и не используется как место для автоматически создаваемых тестовых файлов; запись или перемещение на нём не включены. Нельзя считать тест на SSD F: доказательством выигрыша HDD.

Метрики: суммарное время, полезные МБ/с, задержки p50/p95/p99, число файлов и открытий, порядок запросов, количество конкурентных задач, контрольный хеш содержимого, фактически прочитанные/записанные байты, кэш и повторяемость. Для реального теста алгоритма надо доказать, что контрольная и «Зебра»-раскладки действительно различаются, показать их карту и стоимость их создания; симулятор сам этого не подтверждает.

## 007. Границы островков

Файловый объект → VCN → LCN/экстенты → раздел/LBA → неизвестные физические дорожки. В Windows FSCTL_GET_RETRIEVAL_POINTERS возвращает для выделенных частей файла соответствие VCN→LCN, но **не** магнитные координаты. Источник Microsoft: https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_get_retrieval_pointers.

Будущий инструмент: только чтение карты экстентов **у файлов, доступных на чтение**, получение размера кластера/тома, CSV границ и визуальной шкалы. Запрет на дефрагментацию, запись, обнуление, изменение разделов, попытку получить скрытую информацию о сервосекторах. Несовместимые файловые системы/разреженные участки фиксировать явно.

## 008. Механика, торможение и ресурс

Шпиндель при 7200 об/мин: 120 об/с, 8,33 мс/оборот, приблизительно 754 рад/с. Это расчёт от паспортных оборотов. Головка перемещается приводом с голосовой катушкой: разгон, управляемое замедление, установление. Без датчика угла и внутренней сервотелеметрии мгновенную скорость движения головки нельзя восстановить из задержки Windows USB. Динамическое торможение шпинделя при выключении **не** является методом ускорения чтения. Управление моторами и прошивкой в тест не включено.

Для сравнения ресурсных последствий нужны независимые данные о суммарной записи, времени, температуре, нагрузке, парковках, ошибках и доступности SMART. По одному профилю задержек нельзя вычислить увеличение ресурса.

Вторая команда при большом количестве элементов или ошибках может работать долго; при необходимости прервать Ctrl+C. Не публиковать личные пути. ## Результат реальной карты 007D — файл D:\msdia80.dll, 13.11.2026

Источник: консольный вывод автора `uv run python tools/inspect_extents007d.py --file "D:\msdia80.dll" --run`. Windows успешно вернула 28 строк `VCN / длина / LCN`. Кодировка подписи длины отобразилась в консоли как `�������:`; числовые шестнадцатеричные поля читаются без неоднозначности. **Данные измерены на SSD AMD R5SL120G, не на HGST HDD.**

Расчёт по *всем* присланным строкам (см. `tests/test_parse_extents007.py`, который сохраняет числовую исходную трассу как тестовый набор):

| Характеристика | Значение |
|---|---:|
| Строк `fsutil` | 28 |
| Выделенных диапазонов LCN | 14 |
| Невыделенных диапазонов (`LCN = 0xffffffffffffffff`) | 14 |
| Выделенных логических кластеров | 143 |
| Невыделенных логических кластеров | 81 |
| Покрыто логических VCN-кластеров | 224 |
| Первый выделенный LCN | `0x1d52cd` |
| Конец последнего выделенного диапазона, не включая границу | `0x1d535c` |
| Разрывов между последовательными *выделенными* участками LCN | **0** |

**Главный вывод:** 14 отдельных выделенных *логических пробегов*, перемежающихся невыделенными VCN, занимают **одну непрерывную последовательность LCN** (143 кластера). Поэтому утверждение «28 строк = 28 фрагментов на накопителе» **ложно**. На уровне выделенных LCN здесь нет разрывов; это не означает физическую непрерывность ячеек NAND (FTL SSD недоступен) и тем более не доказывает непрерывность магнитных дорожек HDD.

Множество групп имеет логическую длину **16 VCN-кластеров**, причём в пределах каждой группы часть кластеров выделена, часть помечена `LCN = -1`. Это **совместимо с NTFS-сжатием** и заполнением compression unit; также возможен sparse-формат. По одной карте нельзя окончательно доказать, что именно включено. Необходимо отдельно проверить атрибуты:

```powershell
(Get-Item -LiteralPath "D:\msdia80.dll").Attributes
compact /q "D:\msdia80.dll"
fsutil fsinfo ntfsinfo D:
```

`compact /q` запрашивает состояние сжатия, **не включает/выключает** его; `fsutil fsinfo ntfsinfo` показывает параметры тома, в том числе байты на кластер. Если кластер = 4096 байт (пока гипотеза), то выделено 143×4096 = **585728 байт**; не выделено 81×4096 = **331776 байт**; 224×4096 = **917504 байта логического охвата** (возможна округлённая последняя compression unit). Это *не* данные о фактическом расходе NAND или длине файла по NTFS. По инвентаризации длина файла — 904704 байта.

Добавлен [`tools/parse_extents007.py`](../../tools/parse_extents007.py), который обрабатывает сырые ASCII-числовые поля `fsutil` непосредственно в байтах независимо от OEM-кодировки русской подписи «Длина». Инспектор D: теперь выводит структурированный JSON: VCN, LCN, `null` для дыр, число разрывов. Существующие аппаратные ограничения D: и отсутствие операций записи сохраняются. Дополнительно создан [тест на реальной числовой трассе](../../tests/test_parse_extents007.py). **Новая версия программы ещё не проверена на Acer**.

```powershell
git pull --ff-only origin main
uv run python -m unittest discover -s tests -v
uv run python tools/inspect_extents007d.py --file "D:\msdia80.dll" --run
```

Проводится только чтение метаданных SSD. Для магнитного HDD T: политика **read-only** сохраняется. Выигрыш «Гантовой зебры» пока не доказан.
