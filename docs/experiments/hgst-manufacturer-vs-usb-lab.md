### USB: чего мы **не знаем**

В Acer обнаружены два хост-контроллера «AMD USB 3.10 — 1.10 (Майкрософт)» со статусом OK. Это **не** доказательство, что конкретный USB–SATA мост JMicron согласовал **SuperSpeed (USB 3.x)**. У USB 3.x есть обратная совместимость с режимом USB 2.0 High-Speed.

- USB 2.0 High-Speed — номинальные **480 Мбит/с**, то есть **60 МБ/с до протокольных накладных расходов**.
- USB 3.0 / USB 3.1 Gen 1 — номинальные **5 Гбит/с**.
- USB 3.1 Gen 2 — номинальные **10 Гбит/с** (термин `USB 3.1` без `Gen` неоднозначен).
- Наши 37,5 МБ/с соответствуют **300 Мбит/с полезных данных**. Такая скорость **совместима** с USB 2.0 High-Speed, но по одному значению скорости режим связи **не определяется**.
- Если устройство действительно согласовано на USB 3.x SuperSpeed, пропускная способность USB обычно должна позволять передавать 163 МБ/с; однако это **не гарантирует** достижения такой скорости: конкретные HDD-зоны, мост, драйвер, питание, кэширование, ошибки и особенности I/O всё ещё могут ограничивать результат.

**Итог:** на основании имеющихся измерений нельзя ни утверждать «USB ухудшил скорость HDD в 4,3 раза», ни утверждать «USB 3.0 совсем не влияет». Нужна диагностика **конкретного физического USB-подключения**, а затем сравнение с прямым SATA либо заведомо скоростным другим USB–SATA адаптером на том же носителе.

### Проверка режима USB без записи на диск

Официальный **Microsoft USBView** показывает дерево подключённых USB-устройств, дескрипторы и, в том числе, сведения о скорости подключения. Microsoft уточняет, что SuperSpeed следует выяснять с помощью `USB_NODE_CONNECTION_INFORMATION_EX_V2` (а не старого EX, ограниченного High-Speed).

Ресурсы:

- https://learn.microsoft.com/en-us/windows-hardware/drivers/debugger/usbview
- https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/usbioctl/ns-usbioctl-_usb_node_connection_information_ex
- https://learn.microsoft.com/en-us/windows-hardware/drivers/usbcon/usb-faq--introductory-level
- https://www.usb.org/sites/default/files/usb_3_1_language_product_and_packaging_guidelines_final_0.pdf

**Протокол проверки:** найти в дереве USBView подключённый JMicron USB–SATA bridge/HGST (диск 2), записать *активный* режим подключения (High-Speed / SuperSpeed / SuperSpeedPlus), порт, VID/PID, модель моста. Не перепутать `bcdUSB` (возможность по дескриптору) с фактическим режимом линии. Пароли, серийные номера и идентификаторы компьютера перед публикацией обезличить. Только после этой проверки делать интерпретацию вероятного узкого места.

## Диагностика Windows SDK и USBView после установки (12 ноября 2026)

Самим Python-скриптам Zebra Ganta (`lab.py`, `transitions.py`, `analyze_transitions.py`) **не требуется** Windows SDK. Его USBView и диагностические средства полезны для отдельной проверки USB–SATA моста, но не доказывают скорость USB-соединения автоматически.

Предыдущий SDK Doctor нашёл Visual Studio Build Tools 18, но `cl.exe` отсутствовал в PATH обычного PowerShell — это нормально вне Developer Command Prompt. Папка `C:\Program Files (x86)\Windows Kits\10` существовала, но наличия `Windows.h` и `kernel32.lib` прежняя проверка не подтвердила. `wpr.exe` обнаружился в `C:\Windows\System32`; ряд других диагностических утилит не найден. Python под `WindowsApps` может оказаться execution alias.

Обновлённый [SDK Doctor v2](https://github.com/musikfed/ai_video3060_12G/blob/main/tools/windows-sdk-doctor.ps1) проверяет реальные заголовки и библиотеки, запускает VS `VsDevCmd.bat` в отдельном cmd-процессе и различает WindowsApps alias и доступный Python runtime. Никаких драйверов, PATH или настроек Windows он не меняет.

Одна команда на Acer:

```powershell
Invoke-WebRequest 'https://raw.githubusercontent.com/musikfed/ai_video3060_12G/main/tools/windows-sdk-doctor.ps1' -OutFile "$env:TEMP\windows-sdk-doctor.ps1"; powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$env:TEMP\windows-sdk-doctor.ps1"
```

USBView устанавливается не во всяком выбранном наборе SDK; если утилита отсутствует, это не означает неисправности диска. Никакой вывод о физическом seek-time HDD или об ускорении хранения по одному такому обследованию не допускается.
