# Передача первичных CSV с Acer в GitHub — без повторного чтения HDD

**Цель:** передать из `F:\zebra-ganta_ch2\results\` оригинальные записи трёх серий опыта **003**, а также опытов **008** и **009**, чтобы автор и аналитик имели доступ к **каждому измерению**, а не только к скопированным медианам. Данные опытов 004/005 уже есть в репозитории; повторно их копировать не нужно.

**Безопасность:** том **T: NTFS на физическом HGST Disk 2 не открывается и не изменяется**. Скрипт работает только на Acer из `F:\zebra-ganta_ch2` и не запускает эксперименты. Старые каталоги `results\` сохраняются без изменений.

### Что будет опубликовано

| Источник на Acer | Путь назначения в репозитории | CSV |
|---|---|---|
| `results\20261112T185114Z-transitions` | `data/raw/exp003-run1/` | observations.csv (40 строк) |
| `results\20261112T185549Z-transitions` | `data/raw/exp003-run2/` | observations.csv (40 строк) |
| `results\20261112T185935Z-transitions` | `data/raw/exp003-run3/` | observations.csv (80 строк) |
| `results\20261113T120828Z-exp008-ntfs-hgst` | `data/raw/exp008-ntfs-hgst/` | observations.csv (512 строк), summary.csv (4 строки) |
| `results\20261113T123121Z-exp009-size-ntfs` | `data/raw/exp009-size-ntfs/` | observations.csv (180 строк), summary.csv (15 строк) |

Каждый файл CSV копируется **побайтно**, с записью SHA-256 и числа строк в `provenance.json`. **Исходный `manifest.json` на GitHub не отправляется**: там может быть уникальная PnP-цепочка USB-оборудования. Вместо этого публикуется обезличенный паспорт `provenance.json` с разрешёнными экспериментальными полями и SHA-256 оригинального паспорта. Не публиковать логи с серийными номерами компьютера, личные файлы и секреты.

### Действия на Acer (PowerShell)

Сначала получаем новый скрипт и проверяем его тестами; **каждая команда по одной строке**:

```powershell
Set-Location F:\zebra-ganta_ch2
git pull --ff-only origin main
uv run python -m unittest discover -s tests -v
uv run python tools/publish_acer_raw.py
```

Последняя команда — **PLAN ONLY**, проверит наличие всех оригинальных файлов, число строк и набор колонок, выведет SHA-256. Никакого копирования, изменения репозитория или отправки данных пока нет.

Только если список совпадает с ожидаемыми опытами и файл не содержит нежелательной публичной информации:

```powershell
uv run python tools/publish_acer_raw.py --publish
```

Скрипт создаст **только** файлы `data/raw/exp003-run1..run3/`, `data/raw/exp008-ntfs-hgst/`, `data/raw/exp009-size-ntfs/`, затем `git add` только для этих файлов, `git commit` и `git push origin main`. Проверяет чистую рабочую ветку `main`; если есть незакоммиченные изменения отслеживаемых файлов или уже созданные целевые каталоги — **остановится, ничего не удаляя**. При запросе Git-учётных данных авторизоваться штатным Git Credential Manager; **не присылать токен или пароль в чат**.

**После успешного `git push`** файлы будут доступны здесь: `https://github.com/musikfed/zebra-ganta_ch2/tree/main/data/raw`. Тогда можно читать исходные CSV непосредственно через GitHub и проводить более глубокий статистический анализ. Если push не удался, прислать текст ошибки; повторно начинать физические измерения не нужно.

### Почему это требуется для второй книги

Наличие первичных наблюдений позволит перепроверить медианы и выбросы, рассчитать распределения, корреляции и интервалы неопределённости, построить графики из отдельных точек и отделить фактические измерения от моделей. **До успешного push данные остаются только на Acer, и я не могу получить их через GitHub.**
